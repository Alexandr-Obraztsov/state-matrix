# state-matrix v2: матрица состояний бекенд-ручки

## Цель

Агент берёт **спеку одной бекенд-ручки** и строит матрицу: какие входы бывают, какие у них значения, какие сочетания различимы и какой ответ сервер даёт на каждое. Модель агента максимально зажата скриптом: закрытые списки, обязательные ссылки, базовые значения выводит код, а не агент.

Фронт (UI-состояния, деньги, инпуты) и база знаний удаляются полностью.

## Границы

- **Входные материалы:** спека ручки; документы вокруг неё (другие спеки, OpenAPI, Jira/Confluence по ссылкам); схемы БД и миграции; конфиги, флаги, контракты внешних сервисов.
- **Код сервиса не читается.** Матрица описывает «как должно быть», а не «как сделано».
- **Одна модель — одна ручка.**
- **Вне матрицы:** гонки, повторные запросы, идемпотентность. Агент выписывает их в чат отдельным списком со ссылками, без перемножения.
- **Не проверяем** SQL-инъекции и XSS как отдельные варианты, если спека не говорит о них явно.

## Модель

Файл `.states/models/<METHOD>_<path>.json`, поле `version: 2`. Модель старого формата при загрузке получает отказ «формат v1 не поддерживается»; миграции нет.

### Шапка

`endpoint`: `method`, `path`, `spec` (путь к файлу спеки, файл обязан существовать).

### Входы

| Поле | Значение |
|---|---|
| `name` | уникальное имя: `body.items[].qty`, `storage.order.status`, `dep.pvz` |
| `source` | закрытый список: `path`, `query`, `header`, `body`, `caller`, `storage`, `dependency`, `config`, `clock` |
| `type` | закрытый список: `string`, `int`, `number`, `bool`, `enum`, `array`, `datetime`, `ref`, `relation`, `dependency` |
| `facts` | факты типа; у **каждого** факта своя ссылка |
| `from` | ссылка, откуда известен сам вход |
| `contract` | ссылка на контракт; если есть — вход **доверенный** |
| `traps` | ответ на **каждую** ловушку типа: `affects` или `no`, со ссылкой |
| `extra` | добавки агента: `{value, from}` |

**Доверие:**
- Входы из `path`, `query`, `header`, `body` всегда недоверенные.
- Входы из `storage`, `dependency`, `config` доверенные, если указан `contract`. Без ссылки на контракт — недоверенные.
- Доверенный вход получает только допустимую по контракту часть базы, ловушек у него нет.
- У `dependency` сбои вызова (4xx, 5xx, таймаут) остаются всегда: контракт гарантирует форму ответа, а не сам ответ.
- Сборка сообщает, что отброшено по контракту: вход, значения, ссылка.

**Значения входа = база скрипта + ловушки с ответом `affects` + добавки агента.** Групп у входа нет: каждое значение — отдельная колонка-значение. Сливать значения можно только правилом `merge`.

### Типы (`scripts/types.py`)

Названия значений и ловушек **сразу человеческие** и живут в коде: скрипт отдаёт их готовыми, агенту нечего переводить и негде ошибиться.

| Тип | Факты | Значения от скрипта | Ловушки |
|---|---|---|---|
| строка | min, max, required, nullable, pattern | нет поля, null, не строка, пусто, минимум, максимум, больше максимума, обычное | только пробелы, пробелы по краям, многобайтовые символы, управляющие символы, другой регистр |
| целое | min, max, required, nullable | нет поля, null, не число, меньше минимума, минимум, максимум, больше максимума, обычное | ноль, отрицательное, дробное, огромное, число строкой |
| число | min, max, required, nullable | нет поля, null, не число, меньше минимума, минимум, максимум, больше максимума, обычное | ноль, отрицательное, огромное, число строкой, точность |
| да/нет | required, nullable | нет поля, null, true, false, не true/false | «true» строкой, 0 или 1 |
| один из списка | values, required, nullable | нет поля, null, каждое значение списка, значение не из списка | другой регистр, пробелы по краям |
| массив | min, max, unique | нет поля, null, пустой, минимум элементов, максимум элементов, больше максимума | повторы, плохой элемент внутри |
| дата и время | min, max, format | нет поля, null, неверный формат, минимум, максимум, обычное | часовой пояс, 29 февраля, на границе «сейчас» |
| запись в БД | entity | есть, нет, удалена, чужая | — |
| сравнение двух входов | left, right, op | меньше, равно, больше | — |
| внешний сервис | contract, ok (успешные исходы по контракту, названные словами: «найден», «не найден») | каждый успешный исход, ошибка 4xx, ошибка 5xx, таймаут | — |

Внутренние ключи типов в API (`string`, `int`, `ref` …) видит только агент.

Правила вывода базы:
- если `required=false`, значение «нет поля» остаётся, но считается допустимым;
- если `nullable=true`, значение «null» остаётся, но считается допустимым;
- граничные значения выводятся только при заданных `min`/`max`;
- «обычное» значение есть у каждого входа, кроме записи в БД, сравнения и внешнего сервиса. Для правила «проверять по одному» обычным считается «обычное», «есть», «равно» или первый успешный исход соответственно.

### Ответы

| Поле | Значение |
|---|---|
| `id` | `O1`, `O2`, … |
| `status` | целое 100–599 |
| `code` | код ошибки из спеки или пусто |
| `effects` | список `db:<что>`, `event:<что>`, `call:<что>` **или** явное `none` |
| `from` | ссылка |

Пустой список эффектов не допускается: либо эффекты, либо `none`.

### Правила

| Вид | Смысл | Поля |
|---|---|---|
| `merge` | значения входа ведут себя одинаково → одно значение | `input`, `values`, `into`, `when?` |
| `forbid` | комбинация невозможна | `when` |
| `independent` | входы не влияют друг на друга: не больше одного из них отличается от нормы | `inputs`, `when?` |
| `irrelevant` | при условии входы не влияют на ответ | `when`, `inputs` |

Условие `when` — `{вход: [значения]}`, все пары должны совпасть; значения берутся **после** безусловных `merge`.

У каждого правила есть `from` (ссылка) и `status`: `draft` или `approved`. Сборка применяет только `approved`, черновики показывает отдельно.

**Порядок применения фиксирован и не зависит от порядка добавления:**
1. безусловные `merge` сжимают оси;
2. подсчёт сырого числа строк формулой; больше 1 000 000 — отказ с просьбой добавить правила;
3. перебор;
4. условные `merge`;
5. `forbid`;
6. `independent`;
7. `irrelevant`: у строки в `*` уходят входы из **всех** сработавших правил;
8. дедупликация по ключу строки.

**Потолок — 100 строк после правил.** Выше — блок с разбивкой, какой вход сколько строк добавляет.

### Назначение ответов

Агент ставит ответ каждой строке сам: `{outcome, rows, ref}`. Ссылка обязательна и проверяется. Назначение хранится по канонному ключу строки (`name=value|…`) и переживает пересборку, если ключ не изменился.

**Подозрительная пара:** две строки отличаются ровно одним входом, получили разные ответы, но ссылаются на одно и то же место. Скрипт показывает такие пары, решает человек.

### Ссылки

Как в v1:
- `file.md:§N` или `file.md:"текст"` — раздел или текст должен существовать;
- `file:line` — строка должна существовать;
- свободный текст допускается, пустая ссылка — нет.

## Ход работы

| Шаг | Что происходит | Что одобряет человек |
|---|---|---|
| **0 · Разведка** | агент читает все разрешённые материалы и показывает опись: входы по источникам и найденные ответы | опись полная или что добавить |
| **1 · Ответы** | каталог ответов, одним списком | каталог целиком |
| **2 · Входы** | по одному: значения, ловушки, добавки, **предложение безусловных `merge`** | вход вместе с его объединениями |
| **3 · Правила** | `independent`, `irrelevant`, `forbid`, условные `merge` по одному, у каждого эффект в строках | каждое правило |
| **4 · Матрица** | сборка, назначение ответов со ссылками, разбор подозрительных пар | матрицу целиком |
| **5 · Пробелы** | вопросы к спеке без ответа, проверки вне матрицы | — |

Ответы идут до входов, чтобы предложения `merge` опирались на готовый каталог («любая ошибка поля → один и тот же 400»).

Объединение, одобренное на шаге 2, на шаге 3 можно отменить; скрипт покажет, сколько строк вернётся.

## Инструменты MCP

Имена без префикса: сервер уже добавляет `state-matrix`. Повторный вызов с тем же id перезаписывает запись, `remove: true` удаляет её.

| Инструмент | Назначение | Проверки |
|---|---|---|
| `init` | метод, путь, спека | спека существует |
| `outcome` | ответ | статус 100–599, формат эффектов, ссылка |
| `input` | вход | закрытые списки, ссылка у каждого факта, ответ на каждую ловушку, контракт у доверенного. Возвращает полный список значений и число строк до и после |
| `rule` | правило-черновик | входы и значения существуют. Возвращает число строк было/станет |
| `approve` | список id правил | правила существуют и ещё не одобрены |
| `build` | сборка | см. порядок применения, потолок, черновики |
| `assign` | пачка `[{outcome, rows, ref}]` | ответ в каталоге, строки существуют, ссылка |
| `rows` | строки по фильтру: `unassigned`, `suspect`, `outcome=…`, `input=…` | — |
| `status` | шаг, счётчики, черновики, чего не хватает | — |

**Запреты в коде:**
- правило на несуществующий вход или значение → отказ;
- `assign` до `build` → отказ;
- матрица «готова», только если нет черновиков, нет строк без ответа и строк ≤ 100.

### Формат ответов инструментов

Компактный JSON, без markdown. Колонки называются один раз, строки идут массивами.

```
{"ok":true,"input":"region","values":["нет поля","null","не строка","пусто","только пробелы","минимум","максимум","больше максимума","обычное"],"rows":{"raw":729,"now":729}}
{"ok":true,"rows":17,"raw":32805,"drafts":[],"unassigned":17,"suspect":0,"cols":[...],"funnel":[["R1",...],...]}
{"ok":false,"errors":["не ответил про ловушки: «только пробелы», «пробелы по краям»","у максимума длины нет ссылки на спеку"]}
```

Все ошибки вызова возвращаются **одним списком**, чтобы агент исправил их за один повтор.

Описания инструментов — 1–2 строки. Подробности в SKILL.md.

## Скилл (SKILL.md)

- шаги 0–5 с воротами одобрения;
- перед любым вопросом агент показывает **все** данные, о которых спрашивает, markdown-таблицей, рядом — счётчики из `status`/`rows`;
- вопросы всегда с вариантами ответа;
- `approve` вызывается только после явного «да» в чате;
- формат шага: «Шаг N из 5 · …»;
- никаких внутренних обозначений в чате (см. «Язык для пользователя»);
- отказ работать по коду сервиса.

## Язык для пользователя

Пользователь скилла не знает внутренностей и не должен их учить. **Всё, что видно в чате, — простыми словами.**

| Внутри | В чате |
|---|---|
| `merge` | «считать одинаковыми: нет поля, null, пусто → это один случай, потому что …» |
| `irrelevant` | «не влияет: если поле неверное, в сервис ПВЗ не ходим, его ответ не важен» |
| `independent` | «проверять по одному: поля адреса друг на друга не влияют» |
| `forbid` | «не бывает: …» |
| `draft` / `approved` | «ждёт твоего решения» / «принято» |
| `*` в строке | «любое» |
| `O2`, `r05`, `R6` | не показываются: ответ называется статусом и кодом («400 VALIDATION_ERROR»), строка — номером по порядку, правило — своей фразой |
| доверенный вход | «по контракту сервиса адресов пустым не бывает — эти случаи не проверяем» |
| `source`, `type` | «из тела запроса», «из базы», «ответ внешнего сервиса» |
| названия инструментов, JSON, поля модели | никогда |

**Как этого добиться:**
- названия значений, ловушек, источников и типов для людей лежат в коде (`scripts/types.py`) и приходят в ответах инструментов уже готовыми;
- тексты ошибок инструментов написаны по-человечески («не ответил про «только пробелы»», а не `traps: missing blank`): агент может показать их как есть;
- SKILL.md содержит таблицу выше и запрет выводить внутренние обозначения;
- каждое объяснение короткое: одна строка, что это и почему.

## Эталонный пример: поиск ПВЗ

Ручка принимает `region`, `settlement`, `street`, `house`, склеивает их в строку и ищет ПВЗ через внешнюю ручку.

| Шаг | Правило | Строк |
|---|---|---|
| 0 | — | 9⁴ × 5 = 32 805 |
| R1–R4 | считать одинаковыми: в каждом поле «нет поля, null, не строка, пусто, только пробелы, больше максимума» → «неверное» | 4⁴ × 5 = 1 280 |
| R5 | проверять по одному: четыре поля адреса | 65 |
| R6 | не влияет: есть неверное поле → ответ сервиса ПВЗ | 49 |
| R7 | не влияет: сервис ПВЗ ответил «не найден», 4xx, 5xx или таймаут **и** все поля верные (минимум, максимум, обычное) → значения полей | **17** |

Сервис ПВЗ по контракту успешно отвечает «найден» или «не найден» → значения: найден, не найден, ошибка 4xx, ошибка 5xx, таймаут.

Условие R7 перечисляет допустимые значения полей явно: без этого строки с невалидным полем тоже совпали бы с R7 и схлопнулись бы в одну строку «любое» во всех колонках.

Вопросы, которые пример обязан поднять в шаге 5: ответ клиенту при 4xx от ПВЗ; лимит длины склеенной строки (сравнение двух входов); разделитель внутри поля; «не найден» — это 404 или пустой 200; обязательность `settlement`; один ПВЗ или список.

## Что держится только на инструкции

- что одобрение дал человек, а не агент;
- что агент показал данные полностью перед вопросом;
- что ссылка понята верно, а не просто существует.
