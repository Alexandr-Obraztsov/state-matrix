# state-matrix: дизайн устанавливаемого плагина

Дата: 2026-09-22

## Задача

Пользователь даёт агенту спецификацию или указывает на файл с кодом и просит
построить матрицу состояний. Агент подтягивает плагин и идёт по жёсткому
конвейеру: кандидаты в параметры → корзина семантик → параметры с ответами на
вопросы → правила → именованные состояния → сборка → отчёт в чат.

Плагин должен ставиться на чужую машину одной командой и работать без внешних
зависимостей.

## Форма: плагин со скиллом и CLI, без MCP

**Решение.** Claude Code плагин: `SKILL.md` описывает конвейер, `scripts/sm.py`
исполняет. MCP-сервера нет.

**Обоснование.** Строгость обеспечивают сами скрипты: `sm param add` отказывает
без предварительного `sm catalog`, `validate.py` заворачивает модель, у параметра
которой нет `answers`. Эти отказы одинаковы независимо от транспорта, поэтому MCP
не добавил бы ни грамма строгости. При этом MCP стоит: отдельный процесс на
сессию, который при падении молча уносит тулы; зависимость, которую надо ставить
на целевой машине; схемы, занимающие контекст в каждой сессии; невозможность
повторить вызов руками.

Последнее решающее. Инструмент построен на том, что числа печатает скрипт, а не
языковая модель. Если пользователь не может запустить тот же скрипт сам и
получить тот же вывод, главное свойство теряется.

## Зависимости: ноль

Модель хранится в **JSON** (`.states/models/<Имя>.states.json`), а не в YAML.
Причина: PyYAML не входит в стандартную библиотеку, и на чужой машине его может
не быть. Модель теперь пишут тулы, а не человек, поэтому читаемость сырого файла
перестала быть требованием — её обеспечивает `sm show`.

Каталог семантик (`catalog/default.json`) и ответы (`.states/answers.json`) —
тоже JSON. Весь плагин работает на `python3` из коробки.

## Установка

Репозиторий с `.claude-plugin/marketplace.json` в корне:

```bash
/plugin marketplace add https://github.com/<user>/state-matrix
/plugin install state-matrix
```

Для машины без доступа к GitHub — `/plugin marketplace add /путь/к/каталогу`.

## Формат модели

```json
{
  "system": "CommentComposer",
  "source": "src/components/CommentComposer.tsx",
  "mode": "code",
  "params": {
    "value": {
      "type": "string",
      "catalog": "free_text",
      "desc": "Текст комментария",
      "values": ["empty", "blank", "text"],
      "special": ["emoji", "markdown_injection"],
      "from": "CommentComposer.tsx:27",
      "env": false,
      "answers": {"required": "нет", "maxlen": "неизвестно", "trim": "нет"}
    }
  },
  "excluded": {"title": "строка в шапке, ветвления не порождает (:18)"},
  "constraints": [
    {"id": "k1", "forbid": {"value": "empty", "selection": ["inline"]},
     "desc": "В пустом поле нечего выделять",
     "evidence": "CommentComposer.tsx:35", "status": "proven"}
  ],
  "initial": {"value": "empty", "preview": false},
  "transitions": [
    {"event": "type", "when": {"preview": false}, "set": {"value": "text"},
     "evidence": "CommentComposer.tsx:148"}
  ],
  "states": [
    {"name": "Редактирование", "when": {"preview": false, "dragOver": false},
     "desc": "Обычное поле ввода", "evidence": "CommentComposer.tsx:143"}
  ]
}
```

`answers` у параметра обязателен и содержит ответ на каждый вопрос его семантики.
Значение `"неизвестно"` допустимо и попадает в отчёт; отсутствие ключа — ошибка
валидации.

## Тулы

Все подкоманды `sm.py`. Модель первым позиционным аргументом там, где он нужен.

| Команда | Назначение |
|---|---|
| `init <модель> --system --source --mode code\|spec` | завести пустую модель |
| `extract <цель>` | кандидаты в параметры, с номерами строк |
| `catalog <модель> <имя> --type <t>` | **обязательный шаг**: семантика + вопросы; пишет в журнал |
| `catalog list [--type t]` | показать корзину |
| `catalog new --id --names --type --questions --values --special` | завести семантику в проектный каталог |
| `param add <модель> --name --type --values --from --desc [--special] [--env] -a q=…` | добавить параметр |
| `param rm <модель> <имя>` | убрать параметр |
| `exclude <модель> <имя> <причина>` | учесть кандидата как исключённого |
| `rule add <модель> --id (--forbid \| --when + --irrelevant) --evidence [--desc] [--ask]` | правило |
| `rule rm <модель> <id>` | убрать правило |
| `state add <модель> --name --when --desc --evidence` | именованное состояние |
| `state rm <модель> <имя>` | убрать состояние |
| `transition add <модель> --event --when --set --evidence` | переход |
| `rows <модель> [--no-state] [--status s] [--limit n]` | строки матрицы для разбора агентом |
| `answer <модель> <id> proven\|rejected` | ответ человека на `assumed` |
| `show <модель>` | модель человеческим текстом |
| `build <модель> [--root <репозиторий>]` | verify → validate → engine → отчёт |

### Правила отказа

1. `param add` без предшествующего `catalog` для этого имени → отказ с подсказкой.
2. `param add` без `-a` на каждый вопрос семантики → отказ со списком незаданных.
3. `param add` без `--from` → отказ: источник значений обязателен.
4. `rule add` без `--evidence` → отказ.
5. `rule add`, где `evidence` не содержит `file:line` → статус `assumed`,
   и требуется `--ask`: вопрос человеку одной фразой.
6. `state add` без `--evidence` → отказ.
7. Любое значение в `--forbid`, `--when`, `--set`, `--irrelevant`, отсутствующее
   в `values` параметра → отказ.
8. `build` останавливается на первом непройденном шаге; отчёт не печатается.

Журнал обращений к корзине — `.states/.session/<модель>.json`. Он локальный и
в `.gitignore`: протокол проверяется в рамках одной сессии работы над моделью.

## Потолок

Потолок — **100 строк после схлопывания**. Превышение не сообщение, а отказ с
разбором. `build` печатает вклад каждого параметра и ранжированные способы ужаться:

```
ОТКАЗ: 456 строк при потолке 100

вклад параметров:
  viewport    ×3   env-кандидат  → 152 строки
  hostVersion ×2   env-кандидат  → 228 строк
  payMethod   ×3   нет правил схлопывания
  amount      ×4   нет правил схлопывания

дешевле всего:
  1. viewport и hostVersion пометить env → 6 срезов по 38 строк
  2. добавить правило схлопывания для payMethod при cart≠ok

параметры без единого правила: promo, network
  — проверь, влияют ли они на исход вообще
```

**Как определяется env-кандидат:** параметр, которого нет ни в одном `set`
перехода, то есть в рантайме он не меняется.

## Корзина семантик

Пятнадцать записей в `catalog/default.json`. У каждой: `id`, `matches`
(имена, типы), `questions` (обязательные), `values`, `special`.

**Данные:** `free_text`, `identifier`, `formatted_string`, `number`,
`money_amount`, `pagination_limit`, `percentage`, `duration`, `date_time`,
`collection`, `boolean_flag`

**Взаимодействие:** `http_endpoint`, `error_state`, `auth_role`, `file_upload`

**Окружение** (помечаются `env_candidate: true`): `viewport`, `locale`,
`feature_flag`

Вопросы формулируются так, чтобы ответ напрямую порождал значения или исход.
Пример для `error_state`: где показывается ошибка; есть ли повтор; текст из
бэкенда или свой; логируется ли; что с уже введёнными данными.

Проектный каталог `.states/catalog.json` имеет приоритет над дефолтным и
пополняется командой `catalog new`.

## Отчёт

Только markdown в чат, генерируется `report_md.py` из `result.json`. Разделы:
параметры с описаниями и значениями → исключённые → правила → состояния системы
с числом строк → матрица → спецзначения → находки → требующие уточнения.

Агент обязан печатать отчёт целиком, а не пересказывать. Числа в чате и в
`result.json` совпадают по построению.

## Что удаляется

`report/report.html`, `scripts/serve.py`, `.claude/launch.json`, приём ответов
через HTTP POST. Ответы человека переезжают в `sm answer`.

## Проверки

- unittest на движок: детерминизм, срезы окружения, forbid, схлопывание,
  достижимость, пересечение правил, потолок и его подсказки;
- unittest на `sm.py`: каждый из восьми отказов срабатывает;
- unittest на `verify.py`: подложные ссылки и пропущенный кандидат ловятся;
- эталонная модель `examples/CommentComposer.states.json` с известными числами.

## Вне рамок этой версии

- Версионирование семантик каталога и инвалидация моделей при их изменении.
- `extract.py` для бэкенда: эндпоинты, схемы валидации, DDL.
- Сопоставление параметра с семантикой автоматом — сейчас агент выбирает сам
  из того, что напечатал `catalog`.
- Проверка пересечения именованных состояний между собой.
