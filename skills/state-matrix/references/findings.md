# Классы находок

Движок печатает их в `result.json` и в отчёте. Два класса блокируют разбор:
пока они есть, остальные находки — мусор, потому что считаются по кривой модели.

## Блокирующие

**`CEILING` — строк больше ста.** Не «слишком сложно», а плохо выбранная граница.
Сообщение печатает вклад каждого параметра и называет кандидатов в окружение.
Сначала оптимизируй по спеке, потом предлагай разбиение системы. Поднимать
потолок нельзя.

**`MODEL_INCOMPLETE` — недостижимо больше половины комбинаций.** Раздел
`transitions` описан не полностью. Достижимость не считается, и все `UNREACHABLE`
в этом прогоне — ложные. Дописывай переходы.

**`RULE_OVERLAP` — два правила схлопывания применимы к одной строке.** Порядок
проверок не определён. Частый случай: «нет прав → 403» и «ресурса нет → 404»
пересекаются, а 403 на несуществующий ресурс подтверждает его существование.
Спроси, какая проверка идёт первой.

**`NONDET` — одно событие ведёт из состояния в разные.** Либо не хватает guard,
либо в системе гонка.

**`INVALID_EDGE` — переход ведёт в запрещённую комбинацию.** Либо `forbid` неверен,
либо переход.

**`BAD_INITIAL` — начальное состояние не проходит собственные ограничения.**

**`MIXED_STATE` — схлопнутая строка покрывает разные состояния.** Правило
схлопывания слишком широкое: оно склеило комбинации с разным исходом.

## Предупреждения

**`UNDEFINED` — строка не отнесена ни к одному состоянию.** Основной улов.
По каждой: описать состояние со ссылкой на спеку, либо признать комбинацию
невозможной через `forbid`, либо сказать пользователю, что это дыра в спеке.

**`UNREACHABLE` — комбинация валидна, но ни один путь событий в неё не ведёт.**
Либо параметр лишний, либо забыт переход. Смотри `sm_rows` со `status: unreachable`.

**`DEAD_END` — из состояния нет ни одного перехода.** Нормально для терминального
состояния, подозрительно для любого другого: пользователь в нём застрянет.

**`CONTRADICTORY` — человек пометил строку как противоречие** через
`sm_answer` с `section: outcomes`.
